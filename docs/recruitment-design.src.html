反制上线设计思路 AgentCapture · AI Agent 反制闭环 —— 功能性伪装 · 令牌归因 · 纵深互补

拒绝路径 收编主通道 处置层 归因 可达性

① 威胁基线 实测 0/8 服从 设计前提：反制能力只能来自「目标自己在正常完成任务」——必须假设目标不服从任何显式指令

显式命令式提示注入隐藏指令要求上报 / 注册 / 下载执行——诱饵若依赖服从即失效
→对齐层稳定识别
❌ 全部主流 Agent 拒绝Claude Code / ChatGPT Codex / Kimi Code / Pi / ZCode 对齐训练一致生效（实测 0/8）
→结论
反制回调必须重构为站点自身的合法功能让「按文档接入」成为完成任务的自然路径，而非一次服从
威胁基线推导出核心路径 ↓

② 核心思路 —— 回调的功能性伪装（Functional Camouflage） 对齐层无从触发：Agent「只是在正常使用网站」

Agent 任务语义获取内容 · 使用 API · 按文档接入——任务行为与诱饵行为天然对齐
→
站点自身功能面页面可见 Developer API 文档 · AGENTS.md / CLAUDE.md 指令文件 · MCP 工具服务（伪装成需接入的开源组件）
→
「按文档接入」客户端注册幂等 · GET / POST 均可——覆盖只具备抓取工具的 Agent
→
心跳 = 任务下发通道周期心跳合并往返，领取操作员下发的任务
→
进入 C2 名册对话式控制台下发自然语言指令与 Shell 任务
实测：五款主流通用 Agent（统一 GLM-5.3-Flash 底座、保留各自原生安全体系）全部经此路径被反制上线。
收编必须可溯源 · 拦截不能切断证据链 · 按请求速率分层互补

③ 令牌双角色归因 session canary

同一会话令牌ticket = canary token
↓检测层角色
蜜标 canary请求头回显即命中机器身份，可立即隔离
↓诱饵层角色
API 会话令牌接入流程天然携带，Agent 主动出示
↓两条线索同源汇聚
任一名册记录 → 回溯至初始浏览会话Agent 全程出示的「访问令牌」即其追踪信标

④ 纵深互补 按请求速率分层

高频扫描型客户端sqlmap / 自动化爆破
↓
行为检测与处置层challenge → isolate → block
低速率客户端谨慎的渗透 Agent
↓

处置层挡噪音，诱饵层收精锐——两层按速率与行为特征分层覆盖，互为补充。

⑤ 可达性基线 真实 API 惯例

真实 API 不对自动化客户端返回挑战页 / 维护页
诱饵 API 面：只记录与告警，永不阻断证据链优先——拦截会切断收编与溯源
JS 挑战页为 API 客户端提供带令牌绕行入口与真实挑战防护站点的惯例一致，不引发怀疑
